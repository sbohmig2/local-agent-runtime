# Local Agent Runtime v0.5.1

Version `0.5.1` is a compatibility release for runtime-issued model options
and LM Studio tool catalogs used by Finance Vault.

## What changed

- The TypeScript host validates a requested reasoning effort against the fresh
  runtime-issued model option selected by its opaque ID, rather than against
  the base profile. Removed options fail as `model_option_unavailable`, and a
  stale effort capability fails as `reasoning_effort_unsupported`, before a
  provider session is created.
- A continued host session uses the model option's snapshotted reasoning policy
  without depending on another catalog read. The Python runtime still resolves
  every option authoritatively before provider dispatch.
- LM Studio tool and structured-output schemas omit `minLength` and `maxLength`
  only on the provider wire because its grammar compiler rejects those valid
  JSON Schema keywords. Original application schemas remain unchanged and
  authoritative for tool-argument and structured-output validation.
- Codex, Claude, Grok, and OpenRouter schema handling is unchanged.

## Compatibility

The gateway API remains `1.4.0`. Python and TypeScript packages are released
together as `0.5.1`; consumers must upgrade both pins.

The LM Studio translation is deliberately narrow. Removing a length keyword
inside a negative or conditional subschema can make the provider grammar more
restrictive, while the original application schema remains authoritative. The
current Finance Vault tool catalog uses ordinary positive property constraints;
future consumers with negative or conditional length rules should qualify those
schemas with their selected LM Studio version and model.
