# Local Agent Runtime v0.6.0

Version `0.6.0` bounds each provider call's conversation context to the loaded
model's actual capacity and the profile's character ceiling without breaking
multi-turn continuity (LAR-011). Longer valid conversations no longer depend on
provider-side truncation that broke message roles or dropped the active working
context.

## What changed

- Each provider call sends the instructions, the entire current turn with every
  tool request and result since its user message, and then as many complete
  earlier turns, newest-first, as fit. Tool-call/result groups are never split
  and nothing the runtime drops from a prompt is re-executed.
- Capacity is evidence, never fabrication: an optional provider capacity port
  lets LM Studio report the loaded instance's context; every other route keeps
  `capacity_source: unknown` and `capacity_tokens: null`. The profile's
  `max_input_chars` bounds incoming input where it arrives and each call's
  serialized window as the adapter itself sizes it (`prompt_chars`), not the
  retained transcript.
- A mandatory window that cannot fit fails explicitly before any provider
  request: `context_window_exceeded` when the model's capacity is the limit and
  `input_limit_exceeded` when the character ceiling is.
- Small-context output allocation: below 128,000 tokens, one pressured call may
  run with the remaining output space, never below `min(max_output_tokens,
  2048)`; the next roomy call regains the configured value and the session's
  `limits` never change. A provider that stops at the allocated length fails as
  `provider_incomplete`; no truncated answer is reported as complete and no
  partial tool call is executed.
- Consumer resource skills and active-action context remain opaque input: the
  runtime preserves their bounded delivery and adds no resource-specific
  wording, recipe or fallback.
- Cancellation, streaming, redaction and concurrency behavior are unchanged;
  non-target providers keep the complete-result path.

## Contract

The gateway API advances additively to `1.5.0`: every session response gains a
`context` object (`capacity_tokens`, `capacity_source`, `estimated_prompt_tokens`,
`basis`, `reduced`, `dropped_messages`, `configured_output_tokens`,
`allocated_output_tokens`) and a counts-only `context_reduced` event is emitted
per reduced or reallocated round. The TypeScript host exposes `HostSession.context`
and a camelCase `context_reduced` host event; an unknown-capacity reduction
keeps `capacityTokens` and `budgetTokens` as `null`.

## Compatibility

Python and TypeScript packages are released together as `0.6.0`; consumers
must upgrade both pins. The host toolkit compares the API version exactly.
