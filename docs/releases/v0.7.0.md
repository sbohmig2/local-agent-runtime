# Local Agent Runtime v0.7.0

Version `0.7.0` gives consumers per-invocation control over provider-native web
use. It also restores two LM Studio structured-output behaviors that consumers
had before adopting the runtime (LAR-013).

## Changes

- `Invocation` gains the additive field `provider_native_web: bool = True`.
  - When a consumer sets it to `False`, the Codex, Claude, and Grok routes run
    with every provider-native web tool disabled:
    - Codex: `web_search="disabled"`.
    - Claude: `--tools ""` plus a `WebSearch,WebFetch` deny rule.
    - Grok: `--tools ""`, web tools removed by name, `--disable-web-search`,
      and no `GROK_WEB_FETCH`.

    The CLI prompt then forbids every provider-native tool.
  - Operator configuration cannot re-enable web for such an invocation.
  - The default keeps today's behavior. Sessions created through the runtime
    service or HTTP gateway use the default.
  - Routes without the capability now send their disabled form consistently.
- The LM Studio structured-output (`response_format`) schema is sent to the
  provider unchanged, including nested `minLength` and `maxLength`, which LM
  Studio accepts and enforces. Tool input schemas still omit those two keywords
  on the wire, as in `v0.5.1`. The application keeps validating tool arguments
  and final output against the original schemas.
- An LM Studio reasoning model may return its schema-bound answer in
  `reasoning_content` (or `reasoning`) with empty `content`. The runtime accepts
  that answer only when all of these hold:
  - the call is non-streaming, has an output schema, and carries no tools;
  - the response carries neither content nor tool calls;
  - the text fits the output bound and parses as JSON.

  It is then validated against the original schema. Non-empty content always
  wins. Other LM Studio requests and other adapters, including OpenRouter, never
  promote reasoning text.
- A provider grammar refusal remains an explicit failure. The adapter does not
  retry with a weakened schema.

This is a minor release because the public Python contract gains a field. The
gateway API remains `1.5.0` because the HTTP and OpenAPI contract is unchanged.
Python and TypeScript packages are released together as `0.7.0` so consumers
retain one matched runtime identity.

## Compatibility notes

- A third-party `CLIAdapterBase` subclass must accept the new keyword-only
  `native_web` argument of `arguments()` and `environment()`. The shipped
  adapters already do.
- An LM Studio engine that cannot compile string-length keywords in a
  structured-output schema now fails that request explicitly. `v0.6.0` sent
  that engine a grammar without those bounds and rejected any over-long result
  only at application validation. The current llama.cpp engine (2.41.0) accepts
  and enforces the bounds.
