# Local Agent Runtime v0.3.0

Version `0.3.0` adds runtime-issued model options without transferring provider
catalog or execution authority to consuming applications.

## What changed

- `GET /v1/profiles/{profile_id}/model-options` returns the currently available,
  deployment-qualified choices for one configured profile.
- Session creation accepts an optional opaque `model_option_id`; the runtime
  re-resolves it immediately before dispatch and snapshots the exact requested
  model in session provenance.
- Codex uses its bounded structured catalog, LM Studio uses bounded loopback
  discovery, and Claude and Grok use runtime-maintained catalogs where no stable
  machine-readable CLI enumeration exists.
- Configuration supports either catalog-wide task qualification or narrower
  exact-model qualification. Discovery alone never makes a model selectable.
- Missing, stale, removed, task-ineligible, and reasoning-incompatible choices
  fail explicitly without provider or model fallback.
- Generated Python/OpenAPI and TypeScript root/host contracts carry the same API
  `1.2.0` semantics.

## Release assets

rollback restores both previous `0.2.1` asset pins; tags and published assets
are immutable and are never replaced in place.
